# CLAUDE.md

Notes for working on this repo with Claude Code.

## What this is

RealNPCs (formerly enRAGE Westworld, renamed in 0.6.0): an unofficial C# add-on for the enRAGE nemesis mod for Red Dead Redemption 2. It is a separate DLL (`RealNPCs.dll`) that sits next to enRAGE's `NemesisMod.dll` in the game's `scripts` folder. Its data folder is `Documents\Rockstar Games\Red Dead Redemption 2\RealNPCs` (`RealNPCs.ini`, `RealNPCs.log`, saves, diaries, `voices\`); on first start it copies the old `enRAGE-Westworld` folder over, and it refuses to run while `EnrageWestworld.dll` is still in `scripts`. Internal names (namespaces `EnrageWestworld.*`, class `WestworldScript`, folder `addon/EnrageWestworld`) were kept on purpose. Player-facing text must keep saying "an unofficial add-on for enRAGE" and link enRAGE's Nexus page. Story Mode only. Owner: Lex (GitHub ninjaalex888). Read `README.md` for features and `CHANGELOG.md` for history. The full design doc is the project doc `westworld-addon-design.md` in the claude.ai Project "Red Dead Redemption 2 Mods".

## Build

Stack: Script Hook RDR2 + Script Hook RDR2 .NET V2, net48, x64, **C# 7.3** (no newer language features).

```
cd addon/EnrageWestworld
dotnet build -c Release
```

Needs `refs/ScriptHookRDRNetAPI.dll` and `original/NemesisMod.dll`, both from Lex's own install and never committed (`*.dll` is git-ignored). Output: `addon/EnrageWestworld/bin/Release/net48/RealNPCs.dll`. Copy it into the game's `scripts` folder to test.

Built against enRAGE 0.9.5.3. When enRAGE updates: back up its data folder and the old `NemesisMod.dll` first. Then dump both versions' types and members, private ones included, with the private `tests-private/enrage-diff` tool, which reads them without running their code, and diff the dumps. Anything removed or with a changed signature that the add-on names (reflection in `Bridge*.cs`, typed uses anywhere) needs fixing. Then put the new DLL in `original/`, build, and rerun the overlap checks against the new enRAGE strings: new enRAGE text can match old lines of ours.

## Layout

- `Core/` is plain C# with no game calls: people, rumours, letters, diaries, scenes, all the lines (`Voice`, `Grammar`, `Settings`, `Store`).
- `Game/` talks to the game and to enRAGE (`WestworldScript.*.cs`, `Natives.cs`, `Spawner.cs`, `Stalker.cs`, `Bridge`).
- `addon/EnrageWestworld/package/README.txt` is the player-facing readme that goes in the zip (CRLF line endings in the zip).
- `release/` holds the download zip, because the README links to it. One zip at a time.

## Rules that matter

- **enRAGE: permission, and what stays careful (Lex, 2026-10-26).** enRAGE's author permits decompiling, reverse engineering and reusing its code, and Lex lifted every permission limit on enRAGE's records: they may take part in anything anyone else may (despair since 0.6.3, when free). Adapted enRAGE code is credited, its dialogue and text are never copied (the lines stay original; the overlap checks stay), and the decompiled source isn't committed wholesale. Three limits stay as engineering, not permission: no orders while enRAGE is driving someone (`MayDirect`) until a takeover and hand-back exist; no re-dressing a record (enRAGE knows its people by a look fingerprint, and has no method to relearn one person's look: its `Fingerprint(Ped)`, `NameByLook`, `_fpOf` and `Prints` are private bookkeeping, and records are dressed by `OutfitHash` on every spawn, so records' clothes stay alone; never write its fingerprint table by hand). Since the overnight run (2026-10-27, Lex's brief, Tier 1.4) a record may be the stalker and may despair, through record-safe paths: the stalker borrows a record lightly (`Spawner.BorrowLight`: ours to direct, its mission-entity state left to enRAGE, never marked "no longer needed" on hand-back), checks `RecordStalkWhyNot` every second (the MayDirect rules minus our own hold, plus no enRAGE plan due near them or for their gang within the hour) and hands them back the moment enRAGE has a use for them, after 20 minutes at most (`[Stalkers] StalkerRecords`); a record's death by despair or after one of our street fights is booked through enRAGE's own `History` and `SaveRoster` (and `IsAlive` only if enRAGE missed the death; `Fate` stays enRAGE's, since a Fate keeps a record out of its funerals and burials), `[Mind] RecordFates`.
- **No enRAGE code, text or files in this repo** so far. The add-on reads what enRAGE tracks; it writes through enRAGE's own methods where one exists, and otherwise only the direct writes listed in "Writing to enRAGE" below, each followed by enRAGE's own save. Every line of dialogue must be original; do not copy or lightly reword enRAGE's strings. Never commit decompiled enRAGE source.
- If an enRAGE update breaks something, only the feature that needs it should switch off, and the log should say which.
- Never run script mods in Red Dead Online.
- No LICENSE file, on purpose (Lex, 2026-10-26): all rights reserved, so it can be opened later; the notice ends both readmes.
- Writing style for all player-facing text: plain, specific, no filler.
- Settings: add a field in `Settings.cs`, a line in `ToIni()`, clamp it in `Clamp()`. Bump `CurrentVersion` when adding options so old inis are rewritten with the new lines (values kept).
- Native out-parameters use 8-byte slots.

## Writing to enRAGE (audit, 2026-10-26)

Lex asked for the bridge's writes to be audited so the docs say what really happens. Reading is free (reflection or enRAGE's own types, read only). Writing goes through enRAGE's own methods where one exists; where enRAGE has none (it does the same thing inline in its own code), a direct write is allowed only if it's on this list, followed by enRAGE's own save, and logged. Lex's call on the mind design (2026-10-26, the private Claude Doc "RealNPCs: the NPC Mind"): RealNPCs shares traits and what happens to people back to enRAGE, so this list grows by two (deaths, built in 0.6.3; tempers, with the traits), and nothing else is added without Lex.

Through enRAGE's methods: `Grace` (quiet while still); `WorldNotice`, `Feed`, `GrudgeNotice`; `ChronicleDeed` (AddDeed); `AddThought`, `Mind.Remember`, `History`, `Mind.SetGoal`, the record's own `AddHate`, `AddFear` and `Touch`; `NewRecord` (enRAGE's person generator) and `FitKinToLife`; `IntelNotice`; `SaveRoster` and `SaveWorld`; the settings panel's `Toggle` and `_reload`. Read only, by reflection: `GunMelee.KnockedOutByGunButt` (the people ledger, to tell the knocked out from the dead).

How they fail: the typed writes are compiled against NemesisMod.dll, so a field an enRAGE update renames throws when the feature runs, and its `Safe` guard switches that one feature off and logs it. The reflection writes (`Bridge.Set`, the plan's three) used to skip a missing property in silence; since the audit they log `enRAGE setting <Type>.<name> failed` once.

Files: RealNPCs never modifies NemesisMod.dll or enRAGE's data files directly; enRAGE writes its own saves after the calls above. The one file of enRAGE's that RealNPCs edits is NemesisMod.ini, from the settings panel, only when the player changes an enRAGE setting there, after a backup (`RealNPCs\backup`). One other mod's file is edited too: CasualHookups.ini in the game folder (once, by `HookupsSetUpOnce`, and from the panel; see "CasualHookups").

## The people ledger (0.6.3, step 1 of the mind design)

- What already existed: one `PersonState` per person of every kind (residents, enRAGE's townsfolk by "folk:" key, its records by id). Step 1 adds our own facts, starting with deaths; traits and mirrors of enRAGE's people are step 2.
- Core: `Core/Deaths.cs` (`DeathEntry`: id, name, kind resident|folk|record, game minute, town and place, how, by player|self|another|unknown and who, in view, told to enRAGE; `DeathLedger`: `Note` takes the same person within 120 game minutes as one death and fills in what the first note lacked, `Of`, `ByOf`, `KnockedOut` (enRAGE's `LooksKnockedOut`: incapacitated, its gun-butt test, weapon group 2685387236 or 308416707), `Describe`, `Counts`, cap 1500). `Store.Deaths` with `DeathOf` (an index rebuilt after each change) and `NoteDeath`; `Fix` makes it for old saves; `Rewind` drops deaths after the cut, un-marks the residents who died after it (never a post's keeper or the fled) and passes deaths told to enRAGE to `RewoundShares`. `Engine.NoteDied(entry)` is the one way in and marks a resident `Dead`. `Engine.HasDied`: townsfolk, ours or enRAGE's; a saved resident, their `Dead` flag alone (the posts code clears it when a keeper turns out only shot down, `HolderOf`), an unsaved one, ours; enRAGE's records, enRAGE only, since it brings some back on purpose.
- Game: `Game/WestworldScript.Ledger.cs`. `LedgerStep` runs from `Tick04` before the player-control check, under its own `Safe` ("people ledger"), every 500 ms, never in a story mission. `KnownAt` looks a handle up once (again if the model changes, or every 10 s while it's nobody): a bound resident who keeps no counter, a record, or a named townsperson; never a story model, a child or a counter model. A known handle the game calls dead is noted once, unless `KnockedOutWhy` says out cold (then it's looked at again next time). `LedgerNote` takes how from the cause of death (`Weapons.Phrase`), by from the source of death, the town and whether it was in view. Callers: the scan, `ResidentsPrune` (which now skips the knocked out; before, a resident knocked out in a brawl was marked dead), `DespairDied` (no knocked-out test: they're known dead), hermits, gatherings, and `VacatePost` (the successor path only; keepers who `survive` never enter the ledger).
- Shared with enRAGE ([Mind] `ShareWithEnrage`, on, settings version 58): 4 s after a townsperson's death, if enRAGE's `Acquaintance.Dead` is still false, `Bridge.MarkFolkDead` sets it and `_peopleDirty`. A shared death that a reload undid is taken back 30 s later if enRAGE's own save point (`[SavePoints] AutoRestore`, which restores people.json) didn't already. `despair:rolled2` is not rewound.
- The overlap check flags `'KnockedOutByGunButt'` (enRAGE's method name, which the bridge needs to call it), accepted like `'_worldCatchingUp'`: code names, not text. The knocked-out probe (0.6.3; Lex beat a man meaning to knock him out and couldn't tell whether he died): anyone within 60 m the game has down (dead or incapacitated) whom the rule calls only knocked out is logged `LEDGER out cold: name (why; the game's incapacitation time left N)` and followed: `LEDGER came to:` (got up, after N s), `LEDGER died where they lay:`, or `LEDGER lost` (gone from the world while down); F7 `TEST ledger:` counts them. The game has a real knocked-out state (`TASK_KNOCKED_OUT`, `IS_PED_INCAPACITATED`, `_GET_INCAPACITATION_TIME_REMAINING`, `REVIVE_INJURED_PED`); whether a man beaten down by fists ever gets up is what the probe will show. Log `LEDGER died: name (kind, how, by whose hand, town, in view)`, `LEDGER told enRAGE:`, `LEDGER took back`; F7 `TEST ledger:` (kept by kind, noted, told, taken back, waiting, known people within 50 m, the last). Offline: ticktest `LedgerTest`.
- Seen before the ledger: enRAGE marked Gabriel Ridley (the wall) and Alonzo Draper (the knife) dead itself; Pope McCrae (16:11) is still alive in its people.json. If enRAGE brings him back, he's a case for the revived dead (step 10). Not yet seen in game: the ledger itself.

## Stalkers (current design, 0.6.0)

- Trigger (0.6.0, `WestworldScript.Hosts.cs`): every `StalkerEveryMinutes` of play (Game.GameTime) a roll at `StalkerChance`; a hit (or `StalkerKey`, 0) makes one due (`_stalkDueSince`). A due stalker waits for a clear moment (outdoors, no story mission, no lawmen, not fighting, not in water, screen not fading), then `StalkerCandidate` turns the person within `StalkerNearbyMetres` with the highest `StalkerPick.Score` (enRAGE townsfolk via `AcquaintanceAt` + their `PersonState`; residents only if already bound in `_resBind`; passers-by score 0). Never enRAGE full records (`RecordAt`; enRAGE runs them), lawmen, children, story models, indoors, anyone `CanDirect` rejects, in a Director scene or a wake act, or nearer than 12 m (the 7 m "caught" check). `Stalker.Adopt` borrows them (`Spawner.Borrow`: mission entity, in `Ours` and `Borrowed`); `Spawner.Release`/`CleanupAll` always hand borrowed peds back (`GiveBack`: clear tasks, unblock events, wander, no longer needed), never delete. Nobody for 3 min (or at once for the key): a spawned stranger, the old way, if `StalkerStrangers`. Revenants (Fallen.ReturnAt) are unchanged. After a stalker ends, the next roll counts from then.
- Spawn spots: `GET_SAFE_COORD_FOR_PED` always returns false in RDR2 (seen in game, 0.5.5), so `Natives.StandSpot` falls back to `GET_GROUND_Z_FOR_3D_COORD` (from the player's height first, never inside an interior).
- Behaviour (0.5.5): follow, stare, freeze when watched, hide. Player still for 20 s (no movement or move input; the camera is ignored) -> Circle at 6-10 m; any movement -> Retreat to a hidden spot 45-70 m out (`CoverSpot`), then Lurk. Lasts `StalkerMinutes` (default 120).
- Settings (0.6.0, version 19): `[Stalkers]` master `Stalkers`, StalkerKey, StalkerEveryMinutes, StalkerChance (per roll), StalkerNearbyMetres, StalkerStrangers, appear (strangers and turning up behind you again)/follow/stare/circle/hide distances, StalkerStillSeconds, StalkerWhenStill (mix / eerie / circle / watch / rush; rush stops at 3.5 m and never attacks; mix, the default, picks one each time), StalkerActMin/StalkerActMax (2/30, settings version 31: a new distance each time he comes in), StalkerMutters. `Stalker` holds the live `Settings` object, so panel or ini changes apply at once. A revenant stalker needs West World on too.
- Eerie acts (`Game/Stalker.Acts.cs`, catalogue in `Core/StalkerActs.cs`): `Mode.Act` sprints (speed 3, one nav order, re-sent only if he stops short; the old 1.5 s re-orders made him stop and start; smooth in game, 0.6.1) to a distance picked between StalkerActMin and StalkerActMax (`_actR`, new for each spot; moving round you walks unless the spot is over 15 m off; creep is skipped within 8 m), then Pause (face and stare) -> next act -> Pause, moving round the player every 3-4 acts. Animations are townsfolk gestures (`ai_gestures@gen_male|gen_female@standing@silent|speaker`, clips per sex, `_f_` front-facing clips where they exist; `TASK_PLAY_ANIM` flags Upperbody 8 | Secondary 16, see `eScriptedAnimFlags`, which differ from GTA's; if `IS_ENTITY_PLAYING_ANIM(..., 3)` doesn't see one, it is retried with flag 0, and one success switches all gestures to flag 0 for the session; the head-shake passed on the upper body in game, 0.6.1) and the few Online emotes Story Mode has (`script_mp@emotes@<name>@male@unarmed@full`, flag 0), loaded without blocking, played once facing (within 20 degrees); twists use `_SET_ENTITY_ANIM_SPEED` (freeze logs `_GET_ENTITY_ANIM_CURRENT_TIME` before and after to show whether it held). Scenarios use `TASK_START_SCENARIO_IN_PLACE_HASH`. Creep and shift (`ActStep.Creep`/`Shift`) use "seen" = on screen and clear line of sight, with the stalker ticking every 50 ms while they run: creep walks to 4 m from the player only while unseen (`_SET_PED_CROUCH_MOVEMENT`, then `SET_PED_STEALTH_MOVEMENT` if that didn't take, logged; `Spawner.StandUp` undoes both on every exit and hand-back) and `CLEAR_PED_TASKS_IMMEDIATELY` when seen moving; shift teleports him (like `Relocate`) to a spot 60-180 degrees round at the act distance that the camera can't see (`ShiftSpot`), only after he has been seen since the last shift, 1-3 times. Checks poll and pass on the first frame it runs: anim within 1.5 s, scenario within 6 s (a start after 2 s is logged); two failures (or a missing dict) drop the act for men or women for the session. `Stalker.ProbeActs` (after "Ready") looks up every animation set once and logs `STALKER acts: N of M ... missing: ...` (also `TEST stalker acts` in F7). Watching him changes nothing in this mode; moving ends it (scenarios end with CLEAR_PED_TASKS so props aren't left hanging, anims snap off).
- **The rdr3_discoveries dumps list Online content too: a name being in them doesn't mean Story Mode has it.** In game, 25 of 28 `script_mp@emotes` dicts don't exist (`DOES_ANIM_DICT_EXIST` false; 22 in the 0.6.0 log, then gentlewave, look_yonder and cougar_snarl in the 0.6.1 probe); respectful_bow, pointlaugh and prospector_jig do and played. The four `ai_gestures@gen_male|gen_female@standing@silent|speaker` dicts exist (0.6.1 probe). 20 of 26 scenario starts worked; gravedig and hammer never did and scrub once in three (all with props). The creep's stealth walk never took; `_SET_PED_CROUCH_MOVEMENT` did (0.6.1). Only the in-game probe proves an animation set exists.
- Failed spawns retry after 1, 2, 4, 8, then 10 minutes. The log says what a stalker is waiting for (`STALKER due, waiting: ...`).
- Confirmed in game (0.5.5): spawning, following, circling, running to cover. Not yet seen: the watch and rush modes and the new hour settings.
