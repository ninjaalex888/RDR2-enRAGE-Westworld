# CLAUDE.md

Notes for working on this repo with Claude Code.

## What this is

RealNPCs (formerly enRAGE Westworld, renamed in 0.6.0): an unofficial C# add-on for the enRAGE nemesis mod for Red Dead Redemption 2. It is a separate DLL (`RealNPCs.dll`) that sits next to enRAGE's `NemesisMod.dll` in the game's `scripts` folder. Its data folder is `Documents\Rockstar Games\Red Dead Redemption 2\RealNPCs` (`RealNPCs.ini`, `RealNPCs.log`, saves, diaries, `voices\`); on first start it copies the old `enRAGE-Westworld` folder over, and it refuses to run while `EnrageWestworld.dll` is still in `scripts`. Internal names (namespaces `EnrageWestworld.*`, class `WestworldScript`, folder `addon/EnrageWestworld`) were kept on purpose. Player-facing text must keep saying "an unofficial add-on for enRAGE" and link enRAGE's Nexus page. Story Mode only. Owner: Lex (GitHub ninjaalex888). Read `README.md` for features and `CHANGELOG.md` for history. The full design doc is the project doc `westworld-addon-design.md` in the claude.ai Project "Red Dead Redemption 2 Mods".

## Build

Stack: Script Hook RDR2 + Script Hook RDR2 .NET V2, net48, x64, **C# 7.3** (no newer language features).

```
cd addon/EnrageWestworld
dotnet build -c Release
```

Needs `refs/ScriptHookRDRNetAPI.dll` and `original/NemesisMod.dll`, both from Lex's own install and never committed (`*.dll` is git-ignored). Output: `addon/EnrageWestworld/bin/Release/net48/RealNPCs.dll`. Copy it into the game's `scripts` folder to test.

## Layout

- `Core/` is plain C# with no game calls: people, rumours, letters, diaries, scenes, all the lines (`Voice`, `Grammar`, `Settings`, `Store`).
- `Game/` talks to the game and to enRAGE (`WestworldScript.*.cs`, `Natives.cs`, `Spawner.cs`, `Stalker.cs`, `Bridge`).
- `addon/EnrageWestworld/package/README.txt` is the player-facing readme that goes in the zip (CRLF line endings in the zip).
- `release/` holds the download zip, because the README links to it. One zip at a time.

## Rules that matter

- **No enRAGE code, text or files in this repo.** The add-on reads what enRAGE tracks and changes things only through enRAGE's own methods. Every line of dialogue must be original; do not copy or lightly reword enRAGE's strings. Never commit decompiled enRAGE source.
- If an enRAGE update breaks something, only the feature that needs it should switch off, and the log should say which.
- Never run script mods in Red Dead Online.
- Writing style for all player-facing text: plain, specific, no filler.
- Settings: add a field in `Settings.cs`, a line in `ToIni()`, clamp it in `Clamp()`. Bump `CurrentVersion` when adding options so old inis are rewritten with the new lines (values kept).
- Native out-parameters use 8-byte slots.

## Stalkers (current design, 0.6.0)

- Trigger (0.6.0, `WestworldScript.Hosts.cs`): every `StalkerEveryMinutes` of play (Game.GameTime) a roll at `StalkerChance`; a hit (or `StalkerKey`, 0) makes one due (`_stalkDueSince`). A due stalker waits for a clear moment (outdoors, no story mission, no lawmen, not fighting, not in water, screen not fading), then `StalkerCandidate` turns the person within `StalkerNearbyMetres` with the highest `StalkerPick.Score` (enRAGE townsfolk via `AcquaintanceAt` + their `PersonState`; residents only if already bound in `_resBind`; passers-by score 0). Never enRAGE full records (`RecordAt`; enRAGE runs them), lawmen, children, story models, indoors, anyone `CanDirect` rejects, in a Director scene or a wake act, or nearer than 12 m (the 7 m "caught" check). `Stalker.Adopt` borrows them (`Spawner.Borrow`: mission entity, in `Ours` and `Borrowed`); `Spawner.Release`/`CleanupAll` always hand borrowed peds back (`GiveBack`: clear tasks, unblock events, wander, no longer needed), never delete. Nobody for 3 min (or at once for the key): a spawned stranger, the old way, if `StalkerStrangers`. Revenants (Fallen.ReturnAt) are unchanged. After a stalker ends, the next roll counts from then.
- Spawn spots: `GET_SAFE_COORD_FOR_PED` always returns false in RDR2 (seen in game, 0.5.5), so `Natives.StandSpot` falls back to `GET_GROUND_Z_FOR_3D_COORD` (from the player's height first, never inside an interior).
- Behaviour (0.5.5): follow, stare, freeze when watched, hide. Player still for 20 s (no movement or move input; the camera is ignored) -> Circle at 6-10 m; any movement -> Retreat to a hidden spot 45-70 m out (`CoverSpot`), then Lurk. Lasts `StalkerMinutes` (default 120).
- Settings (0.6.0, version 19): `[Stalkers]` master `Stalkers`, StalkerKey, StalkerEveryMinutes, StalkerChance (per roll), StalkerNearbyMetres, StalkerStrangers, appear (strangers and turning up behind you again)/follow/stare/circle/hide distances, StalkerStillSeconds, StalkerWhenStill (mix / eerie / circle / watch / rush; rush stops at 3.5 m and never attacks; mix, the default, picks one each time), StalkerActMin/StalkerActMax (2/30, settings version 31: a new distance each time he comes in), StalkerMutters. `Stalker` holds the live `Settings` object, so panel or ini changes apply at once. A revenant stalker needs West World on too.
- Eerie acts (`Game/Stalker.Acts.cs`, catalogue in `Core/StalkerActs.cs`): `Mode.Act` sprints (speed 3, one nav order, re-sent only if he stops short; the old 1.5 s re-orders made him stop and start; smooth in game, 0.6.1) to a distance picked between StalkerActMin and StalkerActMax (`_actR`, new for each spot; moving round you walks unless the spot is over 15 m off; creep is skipped within 8 m), then Pause (face and stare) -> next act -> Pause, moving round the player every 3-4 acts. Animations are townsfolk gestures (`ai_gestures@gen_male|gen_female@standing@silent|speaker`, clips per sex, `_f_` front-facing clips where they exist; `TASK_PLAY_ANIM` flags Upperbody 8 | Secondary 16, see `eScriptedAnimFlags`, which differ from GTA's; if `IS_ENTITY_PLAYING_ANIM(..., 3)` doesn't see one, it is retried with flag 0, and one success switches all gestures to flag 0 for the session; the head-shake passed on the upper body in game, 0.6.1) and the few Online emotes Story Mode has (`script_mp@emotes@<name>@male@unarmed@full`, flag 0), loaded without blocking, played once facing (within 20 degrees); twists use `_SET_ENTITY_ANIM_SPEED` (freeze logs `_GET_ENTITY_ANIM_CURRENT_TIME` before and after to show whether it held). Scenarios use `TASK_START_SCENARIO_IN_PLACE_HASH`. Creep and shift (`ActStep.Creep`/`Shift`) use "seen" = on screen and clear line of sight, with the stalker ticking every 50 ms while they run: creep walks to 4 m from the player only while unseen (`_SET_PED_CROUCH_MOVEMENT`, then `SET_PED_STEALTH_MOVEMENT` if that didn't take, logged; `Spawner.StandUp` undoes both on every exit and hand-back) and `CLEAR_PED_TASKS_IMMEDIATELY` when seen moving; shift teleports him (like `Relocate`) to a spot 60-180 degrees round at the act distance that the camera can't see (`ShiftSpot`), only after he has been seen since the last shift, 1-3 times. Checks poll and pass on the first frame it runs: anim within 1.5 s, scenario within 6 s (a start after 2 s is logged); two failures (or a missing dict) drop the act for men or women for the session. `Stalker.ProbeActs` (after "Ready") looks up every animation set once and logs `STALKER acts: N of M ... missing: ...` (also `TEST stalker acts` in F7). Watching him changes nothing in this mode; moving ends it (scenarios end with CLEAR_PED_TASKS so props aren't left hanging, anims snap off).
- **The rdr3_discoveries dumps list Online content too: a name being in them doesn't mean Story Mode has it.** In game, 25 of 28 `script_mp@emotes` dicts don't exist (`DOES_ANIM_DICT_EXIST` false; 22 in the 0.6.0 log, then gentlewave, look_yonder and cougar_snarl in the 0.6.1 probe); respectful_bow, pointlaugh and prospector_jig do and played. The four `ai_gestures@gen_male|gen_female@standing@silent|speaker` dicts exist (0.6.1 probe). 20 of 26 scenario starts worked; gravedig and hammer never did and scrub once in three (all with props). The creep's stealth walk never took; `_SET_PED_CROUCH_MOVEMENT` did (0.6.1). Only the in-game probe proves an animation set exists.
- Failed spawns retry after 1, 2, 4, 8, then 10 minutes. The log says what a stalker is waiting for (`STALKER due, waiting: ...`).
- Confirmed in game (0.5.5): spawning, following, circling, running to cover. Not yet seen: the watch and rush modes and the new hour settings.

1. Update the version in `EnrageWestworld.csproj`, the title and "NEW IN" section of `package/README.txt`, `README.md` and `CHANGELOG.md`.
2. Build, then zip `RealNPCs.dll` and `README.txt` as `release/RealNPCs-<version>.zip`, replacing the old zip, and update the link in `README.md`.
3. Commit and push. A GitHub Release with the zip attached is nicer than the folder link if `gh` can make one.

## Beats and inner lives

- `Core/WakeBeats.cs`: lines that belong to an act (opening thought per act and stage, a thought each time a pacer reaches the end of the path with the real count, a sentence that stops halfway for a freeze). `Game/WestworldScript.WakeActs.cs` calls them as acts start and step (`Think`, `Feed.Mutter`). Add a new act by adding its lines in WakeBeats and its steps in WakeActs together.
- `Core/InnerLife.cs`: ordinary people's thoughts by trade group, hour, temperament, town and faith; reality musings, rumours and fame comments still come first (`Engine.ResidentThought`). Repeats are tracked in `PersonState.Musings` for saved residents.
- Inner lives part 1 (0.6.1, roadmap 4): `InnerLife.Thought` takes an `InnerLife.Context` (`Engine.ThoughtDay(town)`: game day, and the player's `TalkedAbout` deeds in that town from 2 h to 3 days old). Roll: 0-23 the worry, 24-33 the town's talk, 34-43 the day, 44-48 the era, the rest the old frames (an empty slot falls through to them, remapped). `Core/InnerLife.Worries.cs`: 13 worries (debt, fever, letter, drought, son, courting, feud, bank, drink, savings, tooth, secret, law), each fitted by trade group and age, running `WorryDays` (8) game days: begins, worse, crisis, ends well (`GoodChance`) or badly; a new one's first two days may remember the last (`AfterGood`/`AfterBad`). Nothing saved: all from `Person.Id` + game day (`ArcOf`, `KindAt`, `EndsWell`), so unsaved residents are mid-worry when met and counter keepers (25% in `PostThought`, not in their first 3 days at the counter or 3 days after being shot down) move on visit to visit. Ages for fitting use `Voice.NowYear` (the calendar `BornYear` came from), not `ClockYear`. `InnerLife.Pick` frees only a used-up pool's keys from `told` (it used to clear the whole list, which for saved people is `Musings` and also holds the reality lines already said). Names: family once per person (`|child`, `|son`, `|kin`), creditor, neighbour, sweetheart and destination once per worry (`Residents.FirstName`/`Surname`). `Core/InnerLife.Days.cs`: meals and the small hours by hour, Sunday/Monday/Friday/Saturday by `InnerLife.Weekday` (07:00-21:00), `Era1899`/`Era1907` by `InnerLife.ClockYear`, and the town's talk by deed kind (never names the player). `ReadClock` (Core04) sets both from `GET_CLOCK_DAY_OF_WEEK` (0 = Sunday, confirmed in game: 2 April 1899, a Sunday, read 0; `GET_CLOCK_MONTH` is 0-based; the "CLOCK:" line at load shows both) and `GET_CLOCK_YEAR` (John and a year before 1900 means 1907). F7: `TEST worries` lists bound residents within 40 m with `InnerLife.WorryStatus` (keepers included; F7 only writes to the log, the thoughts show on the ticker). Thought seeds for keepers and residents change every `ThoughtEvery` (45) game minutes in Core04, matching the ticker's 90 s `ThoughtCacheMs`; at 600 the same thought came back for 20 real minutes, which hid the worries. Within `BesideMetres` (3.5 m) a `NearThought` is `Beside`: `TickerBrain` gives the first one (in ranking order) every other turn, with `BesideCacheMs` (30 s) instead of 90 s, and Core04 changes its seed every 15 game minutes. `Engine.FolkThought`: enRAGE townsfolk say `Folks.Thought` 70% when strong (Heart, favour, witnessed, grudge or fear 40+), 30% otherwise, else InnerLife (`Folk.Temper` as Personality; no BornYear, so worries use a steady age 20-64 from the Id). `ResidentThought`: StrangerThought only on the RealityChance roll (same `seed + "h"` check) or 35% of the rest; it used to take ~70% (rumours 50%, fame 35%). The nearest resident within 12 m is always added (rank +10); a non-resident stranger only when `_near` is empty, as before. F7 `TEST near` (`NearStatus`) calls each near person's `Text()` and logs failures instead of hiding them. Offline harness (scratch, not in the repo): compile `Core/*.cs` into a net48 exe and simulate residents over weeks (unfilled slots, a/an, spacing, length over 110, era words, stage order); 0.6.1 run: 256,000 thoughts, 6,008 distinct, worry 22%, day/era/talk 15%.

## Wake acts (0.5.5)

- Identity vs direction: `ResidentEligible` (identity) accepts any adult human incl. soldiers, lawmen, script-owned; `CanDirect` decides movement. enRAGE records and script-owned peds only get passive acts (look-at, ticker thought, voice; no task clears). The army models are enRAGE gang models, so script-owned soldiers are probably enRAGE extras.
- Acts live in `WestworldScript.WakeActs.cs`; each act's words are in `Core/WakeBeats.cs`. Awake (stage 4) is a state: approach, talk, then an ending (plead, escape, wake someone, kneel, or despair, `AwakeningDespair`, default 75). `WakeDemo` (Y) ends the current act and starts the new stage's.
- Despair: `AwakeningDespair` percent, default 75 since 0.6.0 (old inis holding 2 or 10 are raised by `Settings.RaiseOldDefaults`, with the other 0.6.0 defaults), rolled once per awake person (`despair:rolled` in `PersonState.Told`), residents only, free ambient peds only, armed only (`IS_PED_ARMED(h, 4)`); the bullet's owner is the ped itself so `Watch.cs` (which only counts events whose attacker is the player) books nothing as the player's. Unarmed -> kneel. Knife / head-against-wall endings are NOT built (no verified animations).

The scan uses `Posts.BodyVacates`: a body bound this session (`_bodyWas`, kept after unbinding) vacates only the holder it was; an unknown body (an old one after a reload) never vacates a successor while one of the model is alive or within a day of the takeover. The successor is made the next time the game puts the model at the counter, with a different first name; relative 65% (same sex as the model), else a newcomer from elsewhere.
- Outfits: `GET_NUM_META_PED_OUTFITS` is logged once per model; a successor gets preset 1..n-1, equipped with `_EQUIP_META_PED_OUTFIT_PRESET` + `_UPDATE_PED_VARIATION` (enRAGE's pair) only off screen and without line of sight, again each time the game respawns them. No native reads a ped's current preset.

A name drawn with `Draw.Text` over the label looked wrong (another font, and it didn't follow the head like the game's label). Their names show on the ticker ("William Garrity, the gunsmith").
- Kept still: wake acts passive, no despair, out of street scenes (`DramaTick` pool), and stalking already excludes u_ models. Not during missions. enRAGE treats these models as the game's own (`GameNamed`) and doesn't name them.

## Scenes leave a trace (0.6.1, inner lives part 2)

- Names: `SceneCast.Names` (set in `BuildCast` from `SceneNames(a, b, crowd)`, reset for the jealous scene's man/woman/third order): enRAGE's name (`Person.FirstOf`) or a resident's own (`ResidentOf`); a repeated first name becomes the later one's surname. `Scenes.N()` uses them, `StartScene` passes them as the Director's labels, so lines and labels agree (before, enRAGE townsfolk got enRAGE labels and made-up names in the lines). `Director.SwapNamesInLines` swaps the two names in the beats still to come when a fight goes against the script (the cast swap at the brawl).
- Ties (`Core/Ties.cs`, `SceneTie`; enRAGE has its own `NemesisSystem.Tie`, hence the name): `Ties.Effect` maps a scene kind to -1 (argue, brawl, cheat, debt, standoff), +1 (flirt, propose), 0 (smalltalk, gossip, haggle, hosts) or none (songs, tales, pitches, posse, widow, pickpocket, jealous: three people, roles unclear). `NoteSceneTie` (on `StartScene`, so a scene broken up still counts) keeps one tie per pair, only between people who can be met again (`LastingId`: enRAGE folk key, or a regular or already-saved resident); never saves anyone for it. `Store.Ties` (cap `Ties.Max` 300, oldest dropped; `Fix` makes it for old saves; `Rewind` drops newer ones). Log `TIE a & b: kind (warm|hostile|acquainted, N scenes between them)`; F7 `TEST ties`. Every scene line is logged as `SCENE   name (N m from you): line`, and the end as `SCENE over: ...` or `SCENE stopped after i of n beats: why` (scenes are easy to miss in game: anyone within 22 m, behind the player too).
- Thoughts: `Engine.ThoughtDay(town, id)` adds `Context.Ties` (`Ties.Of`, 4 days) and `Context.TownTies` (`Ties.TalkOf`: same town, warm or hostile, under 2 days, not the thinker's own). In `InnerLife.Thought` a fresh tie takes 45% of the worry band (about 9% of thoughts, offline), and town ties share the town-talk band with the player's deeds. 
- Reasons (0.6.1, slice 1 of reactive NPCs, Lex's call: no timer-driven scenes on whoever stands closest): `Core/Reasons.cs` `Between(a, b, tie, day, now, place)` gives the strongest `Reason` (scene kind, strength, why, `BFirst` = b is A in the scene).
